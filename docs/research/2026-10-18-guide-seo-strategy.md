# 買い物ガイドの SEO と執筆・更新方針

調査日: 2026年10月18日

## 提案の要点

ポイントスプリントでは、計算ツールと結びつく主要な記事を先に揃え、その後は月に一度、新規記事と既存記事のどちらに時間を使うか判断する進め方を勧める。Issue #78 の全記事を揃えることや、毎月必ず新規記事を出すことは目標にしない。

質を保って書ける記事は、完成した時点で公開してよい。月1本という間隔に合わせて公開を待つ必要はない。一方、公開済みの記事に誤りや古い商品情報があれば、新規記事の予定を待たずに修正する。

商品リンクだけの差し替えでも、売り切れや価格条件のずれを直せるなら意味がある。ただし、リンクを交換したという事実だけで検索順位が上がるとは言えない。本文の説明が正しければ全面的に書き直す必要はなく、選び方や結論が古くなった箇所まで直すのが妥当である。

以下では、Google の公式説明と、このサイトへの提案を分けて示す。提案する本数や期間は運用の目安であり、Google が推奨する数値ではない。

## 調査で確認できたことと、まだ分からないこと

リポジトリには `/guides/1000yen-items` の記事があり、商品一覧はビルド時に楽天の商品検索から取得する構成になっている。記事本文の更新日 `updated` と、商品の取得日時 `fetchedAt` は別に持っている。記事案は [Issue #78](https://github.com/bmthd/point-sprint/issues/78)、一覧への導線追加は [Issue #183](https://github.com/bmthd/point-sprint/issues/183) にある。

今回は Search Console の実績、検索ボリューム、収益、制作に使える時間を取得していない。そのため、どの記事が最も集客できるか、月何本が最適かは確定できない。Issue #78 の商品検索のヒット件数は、商品を探せるかどうかの材料であり、Google でその記事が検索される回数を示すものではない。また、同 Issue にある競合調査の記述は今回再検証していない。

当面の目的は、買いまわりで迷う人に検索から来てもらい、記事で疑問を解決し、必要なら計算ツールを使ってもらうことと仮定する。以下の記事優先順位は、この目的と現在のサイト構成から判断した提案である。

## 記事数・公開頻度・更新の比較

| 選択肢 | 得られるもの | 判断 |
| --- | --- | --- |
| 記事案をすべて急いで揃える | 異なる疑問に答えるページを早く用意できる | 品質と保守が追いつく範囲なら有用。ただし全件公開を優先しない |
| 月1回、新規記事を追加する | 制作時間を確保しやすく、公開後の反応を次に生かせる | 継続のための予定として有用。公開間隔自体の SEO 効果は期待しない |
| 1本の記事を更新し続ける | その疑問への回答を正確に保ち、説明を深められる | 既存記事には必要。ただし異なる疑問を1本に詰め込まず、必要な記事は新設する |
| 主要記事を先に揃え、追加と更新を併用する | 検索される疑問への対応と、公開後の改善を両立できる | このサイトで勧める方針 |

### 全記事を揃える必要はあるか

Google は、順位付けをページ単位で行う一方、サイト全体のシグナルも使うと説明している。「記事案をすべて公開すると評価が解放される」という仕組みは示していない。[Google 検索ランキング システムのご紹介](https://developers.google.com/search/docs/appearance/ranking-systems-guide)

記事を増やせば、別の疑問に答える機会は増える。ただし、同じ商品一覧の検索条件だけを変えた記事を増やしても、読者にとっての違いが乏しい場合がある。まずは「上限を知りたい」「対象外を知りたい」「あと1店舗で買うものを探したい」という異なる目的に答える記事を揃える方が、このサイトの使い方につながると考える。

### 月1回の公開は SEO に有利か

Google は、サイトを新鮮に見せるために新しいコンテンツを大量に追加しても、全体の順位改善にはつながらないと明記している。内容を実質的に変えず日付だけ新しくすることにも注意を促している。月1回という公開頻度に、それ自体の順位上昇効果があるという根拠は今回確認できなかった。[有用で信頼性の高い、ユーザーを第一に考えたコンテンツの作成](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)

したがって、月1回は「新規記事の公開日」よりも「記事の状態を見直す日」として使うことを勧める。完成した有用な記事は早く出し、次の月は既存記事の改善だけになってもよい。

### 新しい情報が必要な検索ではどうか

Google は、新鮮さが求められる検索に対して、新しい情報を表示する仕組みを持つ。すべての検索で、公開日が新しい記事ほど有利になるという説明ではない。[Google 検索ランキング システムのご紹介](https://developers.google.com/search/docs/appearance/ranking-systems-guide)

このサイトでは、開催中の条件や季節商品の価格・在庫は変わりやすい。一方、「買う順番で結果が変わるか」といった説明は、ルールが同じなら長く使える。この違いに合わせて点検する頻度を変えるのが妥当である。これは公式説明をサイトに当てはめた判断であり、対象の検索で新鮮さがどの程度評価されるかを測定した結果ではない。

## 商品リンクの差し替えと本文の書き直し

更新の量より、古くなった情報と読者の困りごとが解消されたかで判断する。

| 記事の状態 | 必要な更新 | SEO について言えること |
| --- | --- | --- |
| 売り切れ、リンク切れ、送料や価格の条件違いがある | 対象商品を差し替え、本文の説明とも一致させる | 読者が使える一覧を保てる。順位上昇は保証されない |
| 商品の顔ぶれだけが変わり、選び方や説明は今も正しい | 商品一覧を更新し、取得日時を正確に示す | 本文を全部書き直す理由はない |
| 上限や対象条件が変わった | 公式情報を確認し、説明・計算例・結論を更新する | 商品リンクだけでは誤りが残る |
| 検索して来た人の疑問に十分答えられていない | 回答、比較、計算例、注意点を必要な箇所に加える | 内容改善として取り組む価値があるが、成果は検証が必要 |
| 内容は正確で、追加すべき情報もない | 無理に変更しない | 日付や言い回しだけ変える根拠はない |

### 商品を入れ替えるだけでは解決しないケース

Google は、販売元の説明を写しただけで独自の価値がないアフィリエイトページを問題としている。一方で、追加の価格情報、独自のレビュー、商品比較など、価値を加えたアフィリエイトサイトもあると説明している。商品リンクがあること自体を問題視しているわけではない。[Google ウェブ検索のスパムに関するポリシー](https://developers.google.com/search/docs/essentials/spam-policies)

そのため、商品検索の結果が入れ替わるだけで十分に差別化できるとは考えない方がよい。たとえば「あと1店舗」の記事なら、商品を足した場合の追加支出と増えるポイントを、前提付きの計算例で示せる。上限に達している場合や、買わない方が支出を抑えられる場合も説明できる。計算ツールを持つこのサイトなら、そうした判断の材料を加えられる。

実際に使っていない商品を使用レビューとして紹介したり、比較していない商品を「最もおすすめ」と断定したりはしない。取得した商品一覧と、執筆者が確認した事実を区別する。

なお、Google の専用の reviews system は、調査時点の対象言語一覧に日本語を含めていない。英語圏向けの商品レビュー施策を、そのまま日本語記事の順位要因として説明することは避ける。[Google 検索のレビュー システム](https://developers.google.com/search/docs/appearance/reviews-system)

### 更新日と商品の取得日時をどう扱うか

記事の公開日 `published` は初回公開日として残す。本文の説明や比較、主要な商品選定を実質的に見直したときは `updated` を更新し、何を変えたか短く記録することを勧める。ビルドのたびに変わる商品の取得日時 `fetchedAt` は、価格情報の時点として別に表示する。商品取得だけで、記事全体を再確認したようには見せない。

Google は、表示する日付と構造化データの日付をそろえるよう案内している。ただし、日付を指定しても検索結果に表示される保証はない。[検索結果の日付に関するガイド](https://developers.google.com/search/docs/appearance/publication-dates)

サイトマップの `lastmod` は、ページの最後の重要な更新を示す。Google は、本文・構造化データ・リンクの更新を重要な更新の例として挙げている。したがって、主要商品の差し替えでも `lastmod` を変える理由はあり得るが、それは順位上昇の約束ではない。商品一覧の変更を反映するなら、実際に内容が変わった日時を使い、単なる再ビルドの時刻で一律に更新しない。[サイトマップの作成と送信](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

## このサイトで先に書く記事

最初は、既存の「1000円ポッキリ」を含めた4本を、主要な記事として揃える案を勧める。4本という数は、読者の疑問を分けて扱うための目安である。検索順位に必要な最低本数を示すものではない。

| 優先順 | 記事 | 記事で解決する疑問と、加える価値 |
| --- | --- | --- |
| 1 | 既存の「1000円ポッキリで買えるもの」の改善 | あと1店舗で何を買うか。商品が紹介条件に合うかを点検し、買い足しの支出とポイントを比べる計算例を加える |
| 2 | いくら・何店舗買えばいいか、上限から逆算する | 自分の買い物で上限に届くか。前提の違う計算例と、計算ツールで確かめる方法を示す |
| 3 | マラソンの店舗数に数えられない買い物 | 買ったのに数えられないのはなぜか。公式条件と具体例で説明する |
| 4 | 買う順番は関係あるか | 順番で結果が変わるか。同じ買い物を並べ替えて計算し、結果と前提を示す |

各記事は、単独で主な疑問に答えたうえで、詳しい説明が必要な箇所から関連記事へリンクする。たとえば、1000円の記事から対象外の条件の記事へ、上限の記事から計算ツールへつなぐ。内部リンクはページの発見と内容の理解に使われるため、リンク先が分かる文言にする。[Google のリンクに関するベスト プラクティス](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)

「2000円ポッキリ」や消耗品の細分化は、それぞれ異なる選び方や疑問を説明できるときに追加する。「ふるさと納税」などサイトの中心から離れる記事は、まず主要記事の整備と反応の確認を優先する。この順序は、現在のツールとの関連と制作後の保守を考えて提案している。需要の大小は未確認である。

季節記事は、公開後に検索へ反映される時間を見込んで早めに用意する。Issue #78 の「ピークの1〜2か月前」は制作上の仮の目安として扱い、実績を見て調整する。Google が保証する掲載・評価までの期間ではない。

## 最初の3か月の進め方

制作時間が未確定なので、次の期間は仮案とする。期限を守るために記事の確認を省くことは勧めない。

| 時期 | 作業 | 判断すること |
| --- | --- | --- |
| 開始時 | 一覧への導線を整え、Search Console で既存記事の登録状況を確認する | Google が記事を読める状態か |
| 最初の4〜6週間 | 既存記事を改善し、上記の新規3本を完成順に公開する | 各記事が独立した疑問に答え、計算や公式情報で説明を裏付けているか |
| 2か月目 | ページと検索語ごとの反応を確認し、不足する回答を補う。余力があれば次の記事を追加する | 新しい疑問に答える記事が必要か、既存記事の説明が不足しているか |
| 3か月目 | 反応と保守にかかった時間を見て、以後の新規記事数を決める | 月1本で続けるか、既存記事の改善に時間を寄せるか |

月に1本分しか時間が取れない場合は、優先順に進めればよい。その場合も、誤情報や使えないリンクの修正を優先する。公開済みの記事が十分なら、毎月新規記事を出す必要はない。

商品・条件の点検は公開時と月次の見直し時に行い、開催条件の変更やリンク切れを把握したときは随時対応する。季節記事は需要期の前に見直す。毎月本文を全面改稿する運用は想定しない。

## 成果をどう確かめるか

Search Console では、ページ別・検索語別の表示回数とクリック数、クリック率、平均掲載順位を確認できる。記事が検索に登録されているかも、内容の評価と分けて確認する。[Search Console の利用開始ガイド](https://developers.google.com/search/docs/monitor-debug/search-console-start)

公開・改稿の記録には、URL、変更日、答えたい疑問、変更内容、確認した公式資料、次の確認日を残す。可能なら、記事から計算ツールへの遷移と、商品リンクのクリックも別に計測する。これらの計測値から、記事が利用や収益につながったかを判断する。検索順位とは分けて評価する。

| 観測した状態 | 次に確かめること |
| --- | --- |
| インデックス未登録 | クロール・登録状況、内部リンク、Google が取得した内容を確認する |
| 登録済みだが表示が少ない | 想定する疑問と検索語、需要、競合、記事の内容を見直す。記事数だけで判断しない |
| 表示されるがクリックが少ない | 検索語に対する順位と、タイトルや検索結果の説明が内容に合うかを確認する |
| 検索から読まれるがツール利用につながらない | 記事の目的にツールが必要か、説明とリンクの位置が適切かを確認する |
| 複数の記事が同じ検索語で表示される | それぞれの回答の違いを確認する。同じ検索語で表示されるだけで統合を決めない |

月次では直近28日と前の28日を比較し、データが少ない場合は観測期間を延ばす。平均順位は検索語の構成でも変わるため、同じページ・同じ検索語の推移も見る。季節記事は可能なら前年の同時期とも比べる。

Google は、変更の反映に数時間から数か月かかる場合があり、一般には数週間待って効果を見るよう説明している。公開数日で成否を決めたり、数週間で変化がないことだけを理由に全面改稿したりはしない。[Google 検索の SEO スターター ガイド](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)

このサイトの閲覧数は楽天のイベント日程にも左右され得るため、更新後にアクセスが増えても、改稿の効果とは断定しない。公開・更新の記録とイベントの時期を合わせて読み、次に追加する記事と、直すべき記事を選ぶ。
