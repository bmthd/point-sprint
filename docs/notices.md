# お知らせとバージョン

お知らせ（`apps/web/src/routes/-notices/notices.ts`）は、利用者への連絡と、サイトの変更履歴を兼ねる。PR ごとには書かない。利用者に伝えたい変更があったときに 1 件足す。

## バージョンを上げる

変更を伝えるお知らせには `release` を付け、バージョンを上げる。ヘッダーは、バージョンを持つお知らせのうち最新のものを出し、そのお知らせへリンクする。障害の連絡のように、変更でないお知らせには付けない。

- 同じ注文で獲得予定のポイントが変わる変更では、`changesCalculation: true` にして大きい番号を上げる（1.4 → 2.0）。計算の直しと、楽天の規則の変更（SPU の改定、キャンペーンの倍率や上限の変更）がこれにあたる
- それ以外の変更（画面の改善、新しい機能）では、`changesCalculation: false` にして小さい番号を上げる（1.4 → 1.5）
- 番号の上がり方は `notices.test.ts` が確かめる

ヘッダーの点は、最新のバージョンのお知らせから 30 日以内なら緑、過ぎたら灰になる。

## 倍率や上限を変えたとき

マスタ（`packages/domain/src/master/spu.ts`、`campaigns.ts`）の値を変えたら、`sources.ts` の出典と確認日も直す。計算方法のページ（`/calculation`）の表は、これらのデータから作られる。新しいキャンペーンを足したら、`campaignSources` に出典を足す。足し忘れは `sources.test.ts` が落とす。
