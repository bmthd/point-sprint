# プランの保留 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 購入計画（`Plan`）を保留にでき、保留中のプランは他のプランの計算に数えず、そのプランだけを保留でないプランを前提に試算できるようにする。

**Architecture:** `Plan.onHold` を足す。`calculateAll` は保留でないプランだけで計算し、保留中のプランは 1 つずつ「保留でないプラン + そのプラン」で計算し直す。SPU は `spuAchievements` で保留中のプランを外し、保留中のプランの試算でだけ、そのプランが満たす SPU を `planWithSpu` に足してオンにする。保留の切り替えは `planOperationAtom` で作るので、保留を外したときは今の `newlyAchieved` で SPU が自動でオンになる。

**Tech Stack:** TypeScript、valibot、vitest、jotai、Yamada UI v2（`@workspaces/ui`）

**Spec:** GitHub Issue #317（`gh issue view 317`）の「やること」と「決めたこと」

## Global Constraints

- 保留中のプランが 2 つ以上あっても、試算でお互いを数えない。どれも保留でないプランだけを前提にする
- 保留中のプランの中の注文ごとの保留は、今と同じに扱う（`heldEstimate` をそのまま出す）
- 保留中のプランの注文が SPU の条件を満たしても、`SpuMonth` は変えない。そのプランの試算でだけオンとして計算する。保留を外したら `newlyAchievedSpu` で自動でオンにする
- 新しく作るプランは保留にしない（`createPlan` は変えない）
- プラン一覧は並び順を変えず、保留中のプランに「保留中」の印だけ付ける（2026-11-18 にユーザーが選んだ）
- `onHold` は `v.optional(v.boolean())`。保留でないプランはこの項目を持たない（既存の行も新しいプランも変わらない）
- `CURRENT_SCHEMA_VERSION` を 13 から 14 に上げる。移し替えの処理はいらない
- 画面は Yamada UI の部品で組む。見た目のテストは書かない。テストは自分たちの振る舞いだけ

## 計画で決めたこと（確かめてほしい点）

- **保留中のプランの合計は、そのプラン自身のポイント**にする。上限を共有していて、保留中のプランの注文が保留でないプランの注文より日付が早いと、上限を先に取るので、保留でないプランのポイントが試算の中では減る。この減る分は保留中のプランの合計から引かない（内訳と合計を一致させるため）。注文を足すときのプレビュー（`order-add-form`）だけは、今と同じく「数える全プランの合計の増え方」で出す
- **保留の切り替えはプランの設定**（設定ページとデスクトップの設定パネル、`SettingsContent`）に Switch で置く。アカウントの選択の下
- **「保留中」の印**は、プラン画面の見出し（`PlanSwitcher`）、トップの最新のプランのカード、すべてのプランの一覧の 3 か所に付ける。プランの切り替えメニューには付けない
- **プランを保留にしたとき**、そのプランの注文で満たしていた SPU は自動でオフにしない。今の注文の保留と同じく、`spu-loss-notice` がオフにするかを聞く

## Review Focus

1. 上限を共有するプランの片方を保留にする → もう片方は上限を 1 人で使える（Task 2 のテスト）
2. 保留中のプランに楽天ブックスの注文を足す → `SpuMonth` は変わらず、同じ月の他のプランのブックスの SPU もオフのまま（Task 4 のテスト）
3. ブックスの SPU をユーザーがオフにした月に、保留中のプランがブックスで条件を満たす → そのプランの試算ではオン（Task 3 のテスト）
4. 保留中のプランにプレビューで注文を足す → 増えるポイントに、他の保留中のプランの試算の変化が混ざらない。保留でないプランに足すときも、保留中のプランの試算の変化が混ざらない（Task 2 の `totalCountedWith` のテスト）
5. `onHold` を持たない保存済みのプランを読む → 保留でないプランとして扱う（Task 1 のテスト）

```
active = plans.filter(!onHold)

  world = [...active, held]
  coreH = calculateCore(world, shops)
  result = coreH.get(held.id)，heldEstimates は heldEstimate(world, shops, held, orderId, sumOfTotals(coreH))

```
